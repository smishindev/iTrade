# Спецификация гипотезы H3 — `ETF_TOM_V3` (эффект смены месяца)

_9 октября 2026, **до любого запуска** H3. Выбор гипотезы и ключевые решения — владелец 9 октября 2026
([spikes/H3-candidates.md](spikes/H3-candidates.md), вариант A): ранний отказ по 2006–2020 целиком, позиция 80% счёта,
базовый SPY, варианты IWM / QQQ / корзина; после ревью кода (P1.H3.03) — схема «открытие + повтор» (вариант B
ревью): значимость на 2006–2020, повтор в ту же сторону на финале; варианты — только диагностика. Параметры — `config/strategies/etf_tom_v3.toml`; версия стратегии — SHA-256
канонического JSON `{"strategy": <параметры>, "universe": <набор>}` (как в H1/H2); журнал и пре-регистрация —
`docs/research-log-H3.md`. Это **последняя из трёх** гипотез (SCOPE)._

**Гипотеза H3.** Доходность широкого американского рынка сосредоточена вокруг смены месяца. Позиция в индексном ETF с
открытия последней сессии месяца до открытия 4-й сессии следующего месяца даёт **больше денег после издержек**, чем
такие же 4-сессионные позиции в случайно выбранные соседние блоки сессий (§4), с тем же размером, стопом и
издержками.

**Чем отличается от H1/H2.** Там выбирался *инструмент* по графику цены; здесь инструмент один и заранее известен,
выбирается только *время* — по календарю. Уроки H1/H2 учтены: измерение по деньгам счёта, контроль той же частоты и
длительности, издержки при реальном размере.

**Что известно заранее (честно).** Эффект описан в литературе (Ariel 1987; Lakonishok, Smidt 1988; McConnell, Xu 2008)
— он «публичный», после публикации мог ослабнуть. Данные 2006–2020 видены на H1/H2 (другие правила, другие вопросы):
на них смотрели доходности ETF, но не календарные окна. Период 2021–2026 не запускался ни для одной гипотезы.

## 1. Данные, ряд цен, исполнение — как в H1

Без изменений по [STRATEGY_ETF_PULLBACK_V1.md](STRATEGY_ETF_PULLBACK_V1.md): §1 (ряды, сырые цены через `S(d)`),

§6 модель исполнения (порядок событий, LOO/MOO/стоп, издержки, дивиденды, сплиты, расчёты T+3/T+2/T+1).

## 2. Окно смены месяца

Сессии нумеруются по календарю XNYS: в месяце *M* последняя сессия — день **−1**, предпоследняя — **−2**; в следующем
месяце первая — **+1**, вторая — **+2** и т. д.

1. **Вход:** после закрытия сессии, предшествующей дню входа, — заявка **LOO** на открытие дня входа (база: день **−1**),
   лимит `C + 1,0 · ATR20/M` (H1 §4.1, округление вниз до цента). Не исполнилась — окно пропускается (без повторов).
2. **Защитный стоп** (аварийный, у брокера, SCOPE): `C − 3 · ATR20/M` от закрытия сессии решения, GTC.
3. **Выход:** после закрытия дня **+3** — **MOO** на открытие дня **+4** (держим −1, +1, +2, +3: 4 сессии).
4. **Размер:** `q = floor(0,80 · E_t / Lim)` целых акций (по 0,80/N на каждый ETF корзины из N), только на расчётные
   деньги — при нехватке окно пропускается (`settled_cash`), позиция не урезается. Решение — только если член набора.
5. **R** (для отчёта и порога издержек) = результат / `q · (Lim − Stp)`, стоп — аварийный 3 ATR20.
6. Издержки: проверка `RT(q) ≤ 0,10 · q · (Lim − Stp)` (как H2); при позиции ~$2 600 издержки ≈ 0,09% ≈ 0,02R.

Календарь торговых сессий известен заранее (биржа публикует его заблаговременно) — это не заглядывание в будущее.

## 3. Метрики

Как H2 §5: R на сделку с блочным бутстрэпом по месяцу выхода, годовая доходность после издержек, просадка, доля
времени в позиции, ориентиры SPY и равновзвешенный набор (оба — купить и держать, без издержек и налога). Добавочно:
средняя доходность окна в % позиции.

## 4. Случайный контроль (1 000 прогонов на вариант)

Для каждого окна стратегии — **одно окно той же длины `h`**, выбранное равновероятно среди **непересекающихся блоков
по `h` сессий, заканчивающихся у выхода стратегии** (блок самой стратегии — один из вариантов), начиная не раньше чем
через 4 сессии после предыдущего выхода стратегии (деньги T+3 уже расчётные). Тот же ETF, размер, лимит, стоп и
издержки. Перцентиль = доля прогонов с меньшей итоговой прибылью.

_Почему так (ревью P1.H3.03, блокер B1):_ первая схема брала случайный вход в любой день месяца; такие окна сильно
перекрываются, разброс контроля занижен, и стратегия без эффекта получала ≥ 95 в 9–13% случаев вместо 5%. Блочная схема
откалибрована на синтетическом рынке без эффекта (в ревью: 400 прогонов, z-разброс 0,99–1,04; проверка нашей
реализации — в журнале H3).

## 5. Периоды

| Период | Даты | Назначение |
|---|---|---|
| **Открытие** (`validation`) | 2006-01-03 … 2020-12-31 | ~179 окон: значимость базы SPY (решение владельца 9 октября 2026 — у H3 почти нет параметров, а 4 года дают ~48 окон; 2006–2020 — вне данных McConnell–Xu, которые кончаются 2005 г.) |
| **Финальный** | **2021-01-04 … 2026-09-30** | **один запуск** выбранного варианта + `costs_x2` + контроль |

**Окно считается, только если его плановый выход внутри периода** (ревью S2): окно декабря 2020 (выход в январе
2021) не входит ни в один период, окно сентября 2026 — тоже; в финале ~68 окон (январь 2021 — август 2026).

Отдельного периода разработки нет: отладка — независимой проверкой каждой сделки и тестами на синтетике; правила после
пре-регистрации **не меняются** (только исправление ошибок с записью в журнал). В конфигурации `development` совпадает
с `validation` и не используется для выбора.

## 6. Заранее записанные варианты (8 из 20)

| Вариант | Отличие | Тип |
|---|---|---|
| `tom_spy` | база: SPY, вход −1, выход на открытии +4 | кандидат |
| `tom_iwm`, `tom_qqq` | IWM / QQQ вместо SPY | диагностика |
| `tom_basket` | SPY + IWM + QQQ поровну (по 26,7%) | диагностика |
| `tom_entry2` | вход на открытии дня −2 (5 сессий) | диагностика |
| `tom_exit2`, `tom_exit4` | выход на открытии +3 / +5 | диагностика |
| `tom_costs_x2` | фактические издержки × 2 (решения — по модели) | диагностика |

Решает **только база `tom_spy`** (вариант B, решение владельца): остальные варианты показывают, где эффект сильнее или
слабее, но не выбираются — так нет поправки на множественные проверки и «проклятия победителя».

## 7. Открытие (2006–2020) и ранний отказ

1. Проверяется только `tom_spy` с контролем 1 000.
2. **Открытие подтверждено**, если перцентиль контроля **≥ 95** **и** годовая доходность после издержек > 0.
   Иначе H3 отклоняется **без финального запуска**.
3. Иначе — финал одной командой: `tom_spy` с контролем 1 000 и `tom_costs_x2` под одним замком.

## 8. Критерии повтора (финальный период, все одновременно)

1. Перцентиль случайного контроля (итоговая прибыль) **≥ 50** — смена месяца лучше половины случайных окон.
2. Средний R на сделку **> 0**.
3. Годовая доходность после издержек **> 0**.
4. Максимальная просадка **≤ 20%**.

Нижняя граница интервала, число сделок, доля исполнимых, `costs_x2` и соседи — **отчитываются, но не критерии**
(ревью B2: при ~68 окнах значимость на одном финале почти недостижима даже при реальном эффекте; S3: исполнимость здесь
всегда ~100%). Оценка ревью на синтетике: при эффекте +0,3% за окно H3 проходит обе ступени в ~43% случаев, при +0,4% —
~65%; без эффекта — 2–3%.

Невыполнение любого пункта → H3 отклонена; использованы 3 гипотезы из 3 — по SCOPE проект пересматривается.

## 9. Границы проекта

В рамках SCOPE «Границы V1» с изменениями H2 (решения владельца): обычные ETF, только покупки, cash account, вход на
открытии, защитный стоп у брокера, подтверждение каждой сделки. Новое для H3: позиция до 80% счёта на 4–5 сессий,
2 действия владельца в месяц.
