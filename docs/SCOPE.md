# iTrade — границы проекта (v4)

_Версия 4 · 9 октября 2026 · утверждено владельцем (ворота G1). Подробности — [PLAN.md](PLAN.md).
Прежние границы активной торговли — [archive/SCOPE-v3.md](archive/SCOPE-v3.md)._

## Цель
Личная платформа учёта долгосрочного индексного портфеля: видеть деньги во всех местах хранения, правильно считать
израильские налоги, регулярно докупать индекс через IBKR **только с подтверждения владельца** и не тратить на это
больше ~15 минут в месяц.

## Владелец
| | |
|---|---|
| Налоговый статус | Резидент Израиля, не репатриант; наёмный работник с керен иштальмут |
| Капитал | 10 000 ₪ ≈ $3 280 на старте + регулярные взносы (сумма — решение владельца) |
| Пользователи | Только владелец. Без чужих денег и клиентов |
| Время | ~4 часа в неделю на проект; ~15 минут в месяц на работу с портфелем после запуска |

## Стек (решено)
React 19 + TypeScript · C# / .NET 10 + ASP.NET Core · PostgreSQL 18 · IBKR TWS API (C#) + Flex Web Service.
Python — данные, проверки, эталон, архив исследований; без права торговать.

## Границы
- Инструменты: широкие индексные ETF (какие и где — после консультации с бухгалтером); облигационный ETF — по решению.
- Заявки: покупки (LMT/MOC) и редкие продажи при ребалансировке или выводе; без стопов, плеча, шорта, опционов, крипты.
- Каждая заявка подтверждается владельцем; отправляет только `ExecutionService`; при неизвестном результате — сверка.
- Локальное приложение на ПК владельца; без сервера и облака.
- Керен иштальмут и другие места — только учёт (ручной ввод или импорт выписки), без интеграции.

## Правила, которые не нарушаются
1. Деньги — `decimal`/`numeric`; источник истины — брокер и его выписки.
2. Налоговые допущения меняются только с источником и датой; расчёт сверяется с бухгалтером (ворота G4).
3. Живой счёт — только после ворот G6; до этого paper.
4. Новая торговая гипотеза — только через новое решение о рамке и полный протокол фазы 1; 2021–2026 — её единственная
   чистая проверка.
5. Платные сервисы — только если польза > 2 × годовая стоимость.

## Критерии остановки
1. Учёт проще и надёжнее вести в таблице, чем на платформе → упрощаем или останавливаемся (ворота после каждого этапа).
2. Расчёт налогов не удаётся согласовать с бухгалтером → налоговый модуль только как справка, отчёт делает бухгалтер.
3. Любая лишняя или потерянная заявка на живом счёте → стоп заявок и разбор.

## Вне V4
Активная торговля и сигналы, автоматические заявки без подтверждения, сервер, мобильное приложение, мессенджеры,
LLM с правом заявок, интеграция с израильскими пенсионными фондами.
