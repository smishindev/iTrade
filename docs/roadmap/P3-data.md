проверками качества и сверкой двух источников. Ворота: G3. Хранение — PLAN §4._

## P3.1 Инструменты и наборы

### [ ] P3.1.01 · 🤖 Таблицы инструментов · 2 ч
**Где:** `src/ITrade.Domain/Instruments`, `src/ITrade.Infrastructure/Persistence`, миграция.
**Шаги:** `instruments` (внутренний ID, тип, валюта), `instrument_identifiers` (IBKR `conId`, ISIN при наличии),

**Готово, когда:** повторный импорт ничего не дублирует; изменения создают новую запись с датой.

## P3.3 Дневные бары

### [ ] P3.3.01 · 🤖 Таблицы баров и наборов данных · 1,5 ч · после: P3.1.01
**Шаги:** `daily_bars` (инструмент, торговая дата, OHLCV, источник, ревизия), `bar_revisions`, `dataset_versions`, `dataset_files` (путь, SHA-256).
**Готово, когда:** миграция; ограничение «одна текущая ревизия на (инструмент, дата, источник)».

### [ ] P3.3.02 · 🤖 Импорт Parquet-снимков · 2 ч · после: P3.3.01
**Шаги:** чтение снимков Python-конвейера (Parquet.Net), проверка SHA-256 по manifest, запись ревизий.
**Готово, когда:** испорченный файл (другой хэш) отклоняется; повторный импорт ничего не меняет.

### [ ] P3.3.03 · 🤖 Корпоративные события · 1,5 ч · после: P3.3.01
**Шаги:** `corporate_actions` (сплит: коэффициент; дивиденд: сумма, ex-дата, дата выплаты); импорт; неизвестное или противоречивое событие → инструмент помечается «остановлен до разбора».
**Готово, когда:** тест: противоречивые данные останавливают инструмент, а не заполняются предположением.

### [ ] P3.3.04 · 🤖 Адаптер IBKR: подключение только для чтения · 2 ч
**Где:** `src/ITrade.Broker.IBKR` (первый код адаптера), `src/ITrade.Application/Brokers/IMarketDataSource.cs`.
**Шаги:** перенос проверенного кода подключения из спайка; интерфейс только для чтения (бары, contract details); проверка номера счёта.
**Готово, когда:** контрактный тест на paper-счёте получает contract details.

### [ ] P3.3.05 · 🤖 Дневные бары IBKR · 2 ч · после: P3.3.04
**Шаги:** `reqHistoricalData` с соблюдением лимитов частоты; запись как источник `ibkr`; дозагрузка недостающих дат.
**Готово, когда:** бары набора за 5 лет загружены; лимиты не нарушаются (тест на очередь запросов).

### [ ] P3.3.06 · 🤖 Сверка двух источников · 2 ч · после: P3.3.02, P3.3.05
**Шаги:** сравнение Yahoo и IBKR по close, по наличию дат и по сплитам; пороги (например, |Δclose| > 0,5%);
отчёт расхождений; расхождение на последней дате → инструмент не даёт сигналов, пока не разобран.
**Готово, когда:** отчёт формируется; тест на синтетическом расхождении.

### [ ] P3.3.07 · 🤖 Проверки качества на C# · 2 ч · после: P3.3.01
**Шаги:** перенос всех проверок из Python (`quality.py`): дубли, порядок, пропуски значений и сессий, неположительные цены,
OHLC, объём, выбросы, устаревание, сплиты; дифференциальный тест с Python на одних данных.
**Готово, когда:** обе реализации выдают одинаковый список проблем на тестовых наборах.

### [ ] P3.3.08 · 🤖 Ежедневное задание данных · 1,5 ч · после: P3.3.05, P3.3.06, P3.3.07, P2.4.05
**Шаги:** задание «после закрытия»: бары IBKR → проверки → сверка с Yahoo → статус готовности данных на дату.
**Готово, когда:** запуск после пропуска дней догоняет; статус «данные готовы / не готовы и почему» доступен для API.
