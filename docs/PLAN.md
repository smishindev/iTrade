# iTrade — план v4: индекс + платформа учёта

_Утверждён владельцем 9 октября 2026 (ворота G1, P1.G.02). Заменяет план v3 активной торговли —
[archive/PLAN-v3.md](archive/PLAN-v3.md). Границы — [SCOPE.md](SCOPE.md), ворота — [GATES.md](GATES.md),
задачи — [roadmap/](roadmap/README.md)._

## 0. Коротко

- **Деньги — в индексе**, держим долго. Три заранее записанные торговые гипотезы (откат, тренд/моментум, смена месяца)
  не дали преимущества перед случайным выбором после издержек при счёте ~$3 280, а индекс за те же годы давал
  +7,5…+15,7% в год ([spikes/hypothesis-H3.md](spikes/hypothesis-H3.md) — сводка трёх проверок).
- **Платформа** — личный учёт: портфель и партии, израильские налоги, регулярные взносы, ребалансировка, сводка по всем
  местам хранения (IBKR и, возможно, керен иштальмут). Покупки через IBKR готовит платформа, **отправляет — только после
  подтверждения владельцем**.
- **Где держать индекс** решается с бухгалтером ([accountant-questions.md](accountant-questions.md), §9); платформа
  проектируется так, чтобы работать при любом ответе.
- Исследовательский движок фазы 1 **заморожен** как архив и инструмент. Новая торговая гипотеза — только после явного
  нового решения о рамке (SCOPE), не «докруткой»; период 2021–2026 по-прежнему не виден ни одной гипотезе.

## 1. Цель и критерии пользы

| Что | Как поймём, что работает |
|---|---|
| Видеть, сколько у меня денег и как они растут | сводка по всем местам в ₪ и $, доходность (по времени и по деньгам) против индекса; совпадает с выписками |
| Не ошибиться с налогами | расчёт реального прироста и дивидендов совпадает с расчётом бухгалтера на тестовых примерах; выгрузка для отчёта |
| Регулярно докупать без ошибок | план взносов → готовая заявка → подтверждение → исполнение → сверка с брокером; ноль «потерянных» сделок |
| Не тратить много времени | ~15 минут в месяц на взнос и проверку; годовой отчёт — одна выгрузка |

## 2. Стек (без изменений)

React 19 + TypeScript (`web/`) · C# / .NET 10 + ASP.NET Core (`src/ITrade.*`) · PostgreSQL 18 (Docker) ·
официальный IBKR TWS API (C#) через IB Gateway + Flex Web Service для выписок. Python (`src/itrade/`) — загрузка
данных, проверки, эталон для тестов, архив исследований; **Python не торгует**.

## 3. Модули

| Модуль | Что делает |
|---|---|
| `Portfolio` | инструменты, позиции, партии (FIFO), деньги по валютам, пополнения/выводы, корпоративные события |
| `Valuation` | цены и курсы на дату, стоимость портфеля, доходность TWR/MWR в ₪ и $, сравнение с индексом |
| `Tax` | реальный прирост по курсу Банка Израиля, дивиденды и зачёт удержания США, полугодовые суммы, годовая выгрузка |
| `Plan` | целевые доли, план взносов (₪ в месяц), предложения покупок и ребалансировки (полосы отклонения) |
| `Broker.IBKR` | чтение счёта, позиций, исполнений; заявки на покупку (редко); Flex-выписки; сверка |
| `Execution` | единственный, кто отправляет заявки; подтверждение владельцем; при неизвестном состоянии — сверка, не повтор |
| `Reports` | ежемесячная сводка, годовой налоговый пакет для бухгалтера, журнал решений |
| `Web` | экраны: обзор, позиции и партии, взнос/покупка (с подтверждением), налоги, отчёты, настройки |

Ручные места хранения (керен иштальмут, израильский брокер) вводятся вручную или из файла выписки — без интеграции.

### 3.1 Проекты решения (.NET)

| Проект | Ответственность | Может зависеть от |
|---|---|---|
| `ITrade.Domain` | типы и правила: деньги, количество, валюта, инструмент, транзакция, партия, налоговые расчёты как чистые функции | ничего |
| `ITrade.Application` | сценарии (импорт, оценка, план, подтверждение, исполнение, сверка, отчёты); интерфейсы `IBrokerGateway`, `IClock`, хранилищ | Domain |
| `ITrade.Infrastructure` | EF Core / PostgreSQL, импорт Flex и CSV, курс Банка Израиля, цены, файлы, бэкапы | Application, Domain |
| `ITrade.Broker.IBKR` | **единственная** реализация `IBrokerGateway`; **единственное** место со ссылкой на IBApi | Application, Domain |
| `ITrade.Host` | ASP.NET Core API, фоновые задания, отдача React, вход | все |

Тесты: `ITrade.UnitTests` (Domain, Application), `ITrade.IntegrationTests` (Infrastructure на Testcontainers),
`ITrade.ArchitectureTests` (правила ниже), `ITrade.BrokerContractTests` (paper-счёт, вручную), `ITrade.ReplayTests`
(записанные сообщения IBKR, без сети).

Правила (архитектурные тесты в каждой сборке): `Domain` ни от чего не зависит; в `Domain` запрещены `DateTime.Now`,
`HttpClient`, `DbContext`, файлы; на `IBApi` ссылается только `Broker.IBKR`; `IOrderSender` получает только
`ExecutionService`.

## 4. Данные

- **PostgreSQL:** инструменты, счета/места хранения, транзакции (покупка, продажа, дивиденд, удержание, комиссия,
  конвертация, пополнение), партии, курсы Банка Израиля, цены закрытия, корпоративные события, налоговые периоды,
  журнал заявок и событий брокера, журнал решений владельца.
- **Источник истины для денег — брокер** (Flex-выписки и исполнения); платформа сверяет, а не придумывает.
- Деньги — `decimal`/`numeric`, никогда не float. Время в UTC, курсы — на дату по Банку Израиля.
- Данные Yahoo — только для оценки и проверок, не для налоговых расчётов.

## 5. Брокер и исполнение

- Paper-счёт IBKR — для разработки и тестов; живой счёт — только после ворот G6.
- Заявки — только покупки (и редкие продажи при ребалансировке/выводе), типы LMT или MOC, без стопов и плеча.
- Каждая заявка: предложение платформы → экран подтверждения (сумма, цена, издержки, налоговые последствия) →
  отправка → журнал → сверка с исполнениями и Flex. Повторная отправка при неизвестном состоянии запрещена.
- Проверено в фазе 1: подключение переживает автоперезапуск Gateway в 09:25 (11 с), сводка счёта совпадает с
  веб-интерфейсом, котировки без подписки — задержанные 15 мин (для покупок раз в месяц достаточно).

## 6. Налоги (основа — ответы бухгалтера)

Допущения до консультации (см. `config/costs.toml`, accountant-questions.md): 25% с реального прироста при продаже,
зачёт убытков в том же году, удержание США с дивидендов засчитывается, курс — представительный курс Банка Израиля.
После консультации допущения заменяются ответами с датой и источником; налоговый модуль проверяется на примерах
бухгалтера (ворота G4).

## 8. Что не делаем

Активную торговлю, сигналы, стоп-заявки, плечо, шорт, опционы, крипту, сервер/облако, LLM с правом заявок,
мессенджеры. Новая торговая гипотеза — только через новое решение о рамке и полный протокол фазы 1
(пре-регистрация, контроль, ревью, один финальный запуск).

## 9. Риски

| Риск | Что делаем |
|---|---|
| Ошибка в налогах | расчёт сверяется с бухгалтером на примерах; выгрузка — подсказка, а не замена бухгалтера |
| Лишняя или потерянная заявка | один исполнитель, подтверждение, журнал, сверка, никаких повторов при неизвестном состоянии |
| Платформа сложнее пользы | ворота после каждого этапа: если учёт проще вести в таблице — останавливаемся |
| Налог США на наследство, удержание с дивидендов | выбор места и фонда — с бухгалтером (§9 вопросов) до крупных сумм |
| Соблазн вернуться к «торговле» | любая гипотеза — только через новую рамку и протокол фазы 1 |

## 10. Работа с Claude Code

Задачи — по дорожной карте (`/next-task`, `/task`, `/roadmap-status`); коммит начинается с ID задачи; изменения
только в области задачи; деньги — decimal; брокерский код — только в `src/ITrade.Broker.IBKR/`; живые порты IBKR
заблокированы хуками до этапа пилота; изменения налоговых допущений — с источником и датой.
